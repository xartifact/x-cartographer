## 审计过程发现的 Bug 与修复（2026-08-23）

在导入与验证过程中发现并修复了 3 个真实产品缺陷：

### Bug 1：`PATCH /api/stories/:id` 无法更新验收标准

- **现象**：`story update --ac "a;b"` 后 `acceptanceCriteria` 始终为空（description/tags 正常）。
- **根因**：路由 schema 用 camelCase `acceptanceCriteria`，但 `StoryRepository.update` 读 snake_case `dto.acceptance_criteria` → undefined 被跳过。create 路径有手动字段映射，update 缺失。
- **修复**：`apps/server/src/routes/stories.ts` PATCH handler 增加 `acceptance_criteria: input.acceptanceCriteria` 映射。
- **影响**：36 个 story 的验收标准/描述/标签补写成功；全项目 36/37 有验收标准、34 有描述、35 有标签。

### Bug 2：CLI `task update` 缺 `--deps` 参数处理

- **现象**：`xcart task update <id> --deps "a,b"` 静默成功但依赖不写入。
- **根因**：`cmdTask` 的 `update` 分支读取 title/desc/type/priority/estimation/tags/assignee/status，**漏了 deps** —— flag 存在但代码不读。
- **修复**：`apps/cli/src/index.ts` 增加 `const deps = opt(f, 'deps'); if (deps !== undefined) body.dependencies = splitList(deps);`。
- **影响**：131 条任务依赖全部补写成功（此前全被静默忽略）。

### Bug 3：CLI `parseArgs` 拒绝 `-` 开头的 flag 值

- **现象**：`--deps "-llY_abc"` 不生效（nanoid 可能以 `-` 开头），改用 `--deps="-llY_abc"` 才生效。
- **根因**：`parseArgs` 判断 `!argv[i+1].startsWith('-')` 才当作值，`-` 开头的值被误判为下一个 flag。
- **修复**：长 flag 判断改为 `!argv[i+1].startsWith('--')`（`--` 开头才算 flag；短 flag 保持原判断避免 `-s -t` 误判）。
- **影响**：修复前 6 个任务的依赖被写成含 `[`/`]` 的脏 ID，修复后全量覆盖为正确 ID；目前 **131 个依赖任务、0 脏数据、0 悬空引用**。

> 验证流：三项修复均通过手动 API/CLI 回归测试，`task next` 在完整依赖数据下推荐正确。
