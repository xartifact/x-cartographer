## 📋 执行摘要

X-Cartographer 是一个 **AI-Native 的研发需求与任务管理工具**。它基于 LLM 将自然语言需求描述分析为结构化的用户故事，以故事地图可视化规划产品全貌，将用户故事拆解为可执行任务，并提供贯穿研发全流程的任务管理能力（状态流转、看板视图、批量操作、进度追踪）。

故事地图是规划能力之一，而非产品的全部 —— 产品的核心闭环是：**需求 → 故事 → 任务 → 执行 → 追踪**。

### 核心价值主张

1. **AI 驱动的需求分析**: 通过 LLM 自动分析自然语言需求，提取用户角色、功能点和使用场景，并可直接采纳为项目骨架
2. **可视化故事地图**: 以二维地图展示用户故事，支持拖拽重排、筛选与详情查看
3. **AI 任务拆解**: 将用户故事自动分解为 2-4 小时的可执行任务，识别依赖关系
4. **研发任务管理**: 任务状态流转、看板/列表/分组多视图、批量更新、进度统计
5. **数据持久化**: PGlite 数据库 + Drizzle ORM，TOML 导入导出，全量事务写入
6. **标准化导出**: 支持导出为 TOML 格式，便于集成到开发流程

## 🗺️ 用户旅程概览

### UJ-001: AI 需求分析

**目标**: 用户通过自然语言描述产品需求，LLM 帮助分析和结构化需求，并可直接采纳

**关键步骤**:
1. 用户在文本框中输入自然语言需求描述
2. 点击"分析需求"按钮触发 AI 分析
3. LLM 提取用户角色、功能点、使用场景
4. 用户确认或修改分析结果
5. LLM 生成建议的用户旅程
6. 单个/批量采纳旅程与故事，写入项目骨架

**包含用户故事**: US-001, US-002, US-003, US-037

### UJ-002: 故事地图规划

**目标**: 创建和管理用户故事，以可视化故事地图规划产品全貌

**关键步骤**:
1. 为每个用户旅程步骤创建用户故事
2. 使用标准格式：作为[角色]，我想要[功能]，以便[价值]
3. 查看二维可视化的用户故事地图
4. 拖拽调整故事位置与优先级
5. 点击卡片查看详情，使用筛选器聚焦内容

**包含用户故事**: US-004, US-005, US-006, US-007, US-008, US-009, US-010

### UJ-003: 任务拆解与规划

**目标**: 将用户故事拆解为可执行任务，规划优先级、估算与依赖，导出为团队可用格式

**关键步骤**:
1. 选择用户故事进行任务拆解
2. AI 自动生成 2-4 小时的任务列表
3. 设置任务优先级、工时和依赖关系
4. 导出为 TOML 格式（故事地图）
5. Kanban Markdown 导出（待实现）

**包含用户故事**: US-011, US-012, US-013, US-014

### UJ-004: 研发任务管理

**目标**: 以项目为单位的任务全生命周期管理：多项目组织、状态流转、进度追踪、数据持久化

**关键步骤**:
1. 创建和管理多个项目
2. 任务与用户故事状态流转（backlog→todo→in_progress→in_review→testing→done）
3. 批量更新任务状态
4. 查看状态概览与进度统计
5. PGlite 数据库持久化，TOML 导入迁移

**包含用户故事**: US-015, US-016, US-017, US-034, US-035, US-021, US-022, US-023

### UJ-005: 系统配置与帮助

**目标**: 配置 LLM API 和应用设置，提供用户帮助文档

**关键步骤**:
1. 配置多 Provider（OpenAI、Anthropic、X-Herald）的 API 密钥、模型与端点
2. 测试 API 连接
3. 查看快速入门指南（进行中）
4. 浏览帮助文档和 FAQ（待实现）

**包含用户故事**: US-018, US-019, US-020

### UJ-006: 排期规划

**目标**: 基于里程碑/版本模型规划交付，创建版本、将故事排入版本，以 Roadmap 泳道视图呈现交付计划

**关键步骤**:
1. 创建/编辑/归档版本（名称、目标、目标日期、状态）
2. 在故事详情面板将故事排入版本（未排期 = 待规划池）
3. 查看 Roadmap 泳道视图（每版本故事数 + 估算工时）
4. 按版本筛选故事地图与任务列表
5. AI 排期建议（backlog 增强）

**包含用户故事**: US-039, US-040, US-041, US-042, US-043

## 📈 技术架构（当前实现）

### 技术栈

- **前端**: Next.js + React 19 + TypeScript + Tailwind CSS
- **可视化**: React Flow（@xyflow/react）
- **状态管理**: Zustand + React Query
- **服务端**: Hono gateway（apps/server）+ REST API
- **数据库**: PGlite（服务端文件库）+ Drizzle ORM
- **LLM**: 服务端代理（OpenAI / Anthropic / X-Herald via Pi SDK）

### 数据流架构

```
用户输入
  ↓
React 组件
  ↓
React Query / Zustand State
  ↓ (需要 AI)
服务端 /api/llm/* → OpenAI/Anthropic/X-Herald API
  ↓
数据解析和验证（JSON5/jsonrepair 容错）
  ↓
更新 State
  ↓
细粒度 REST 或全树事务 PUT /api/projects/full
  ↓
PGlite 数据库（Drizzle Repository）
```

### 项目结构（Bulletproof React）

```
apps/

│       ├── features/       # requirements / story-map / tasks / projects / settings / data-browser
```

## ⚠️ 风险与挑战

### 技术风险

1. **TOML 导入主键冲突**
   - **风险**: 多个 TOML 文件的语义 ID（UJ-001/US-001）全局冲突
   - **缓解**: 已实现导入时重写为全局唯一 ID（保留语义前缀）

2. **LLM API 稳定性**
   - **风险**: API 调用失败或响应慢
   - **缓解**: 已实现 JSON5/jsonrepair 容错解析、多 Provider 切换

3. **PGlite 数据一致性**
   - **风险**: 服务端文件库在进程崩溃后可能损坏（postmaster.pid 残留）
   - **缓解**: 已实现崩溃恢复（清锁文件/清空重置）+ 全树事务写入

### 产品风险

1. **AI 生成质量不稳定**
   - **风险**: LLM 生成的结果不符合预期
   - **缓解**: 优化 Prompt、提供用户编辑功能、支持重新生成

2. **故事地图与任务管理的定位平衡**
   - **风险**: 产品从"故事地图工具"转向"研发需求+任务管理工具"，功能重心需相应调整
   - **缓解**: 任务管理（状态/看板/批量/进度）已完整实现，是转型的基础
