## 📋 执行摘要

X-Cartographer 是一个基于 AI Native 理念的用户故事地图可视化应用，旨在帮助产品团队通过 LLM 技术快速从自然语言需求描述中生成结构化的用户故事地图，并支持任务拆解和导出功能。

### 核心价值主张

1. **AI 驱动的需求分析**: 通过 LLM 自动分析自然语言需求，提取用户角色、功能点和使用场景
2. **智能用户旅程生成**: 基于需求分析自动生成结构化的用户旅程地图
3. **可视化故事地图**: 二维可视化展示用户故事，横轴为旅程步骤，纵轴为优先级
4. **AI 任务拆解**: 将用户故事自动分解为 2-4 小时的可执行任务
5. **标准化导出**: 支持导出为 TOML 和 Kanban Markdown 格式，便于集成到开发流程

1. **产品经理**

## 🗺️ 用户旅程概览

### UJ-001: AI 辅助需求分析

**目标**: 用户通过自然语言描述产品需求，LLM 帮助分析和结构化需求

**关键步骤**:
1. 用户在文本框中输入自然语言需求描述
2. 点击"分析需求"按钮触发 AI 分析
3. LLM 提取用户角色、功能点、使用场景
4. 用户确认或修改分析结果
5. 系统生成建议的用户旅程

**包含用户故事**: US-001, US-002, US-003

### UJ-002: 用户故事创建与管理

**目标**: 基于用户旅程创建和管理用户故事，支持 AI 辅助生成

**关键步骤**:
1. 为每个用户旅程步骤创建用户故事
2. 使用标准格式：作为[角色]，我想要[功能]，以便[价值]
3. AI 自动生成验收标准建议
4. 用户编辑和完善用户故事
5. 设置优先级和标签

**包含用户故事**: US-004, US-005, US-006

### UJ-003: 用户故事地图可视化

**目标**: 以可视化方式展示用户故事地图，支持拖拽排列和交互

**关键步骤**:
1. 查看二维可视化的用户故事地图
2. 通过缩放和平移浏览全局
3. 拖拽调整用户故事位置和优先级
4. 点击卡片查看详细信息
5. 使用筛选器聚焦特定内容

**包含用户故事**: US-007, US-008, US-009, US-010

### UJ-004: 任务拆解与导出

**目标**: 将用户故事拆解为可执行任务，并导出为开发团队可用的格式

**关键步骤**:
1. 选择用户故事进行任务拆解
2. AI 自动生成 2-4 小时的任务列表
3. 设置任务优先级、工时和依赖关系
4. 导出为 TOML 格式（故事地图）
5. 导出为 Kanban Markdown 格式（任务看板）

**包含用户故事**: US-011, US-012, US-013, US-014

### UJ-005: 项目管理与协作

**目标**: 管理多个项目的用户故事地图，支持团队协作

**关键步骤**:
1. 创建和管理多个项目
2. 保存项目数据到本地存储
3. 导入已有的 TOML 格式故事地图
4. 在不同项目间切换
5. 分享项目链接给团队成员（未来功能）

**包含用户故事**: US-015, US-016, US-017

### UJ-006: 系统配置与帮助

1. 配置 LLM API 密钥和模型选择

3. 查看 API 使用量统计

## ⚠️ 风险与挑战

### 技术风险

1. **LLM API 稳定性**
   - **风险**: API 调用失败或响应慢
   - **缓解**: 添加重试机制、超时处理、错误提示

2. **大规模故事地图渲染性能**
   - **风险**: 大量用户故事时渲染卡顿
   - **缓解**: 使用虚拟滚动、Canvas 优化、按需加载

3. **TOML 格式兼容性**
   - **风险**: 导入导出格式不兼容
   - **缓解**: 严格遵循 TOML 规范、添加格式验证

### 产品风险

1. **AI 生成质量不稳定**
   - **风险**: LLM 生成的结果不符合预期
   - **缓解**: 优化 Prompt、提供用户编辑功能、支持重新生成

2. **学习曲线**
   - **风险**: 用户不熟悉用户故事地图方法论
   - **缓解**: 提供快速入门向导、示例项目、帮助文档

3. **数据安全**
   - **风险**: API 密钥泄露、用户数据丢失
   - **缓解**: 加密存储 API 密钥、本地数据备份、导出功能

## 🎓 最佳实践建议

### 用户故事地图方法论

1. **保持故事原子性**: 每个用户故事只关注一个功能点
2. **INVEST 原则**: 独立(Independent)、可协商(Negotiable)、有价值(Valuable)、可估算(Estimable)、小(Small)、可测试(Testable)
3. **优先级排序**: 高价值 + 低复杂度优先
4. **验收标准 SMART**: 具体(Specific)、可衡量(Measurable)、可实现(Achievable)、相关(Relevant)、有时限(Time-bound)

### AI Prompt 优化

1. **需求分析 Prompt**: 明确要求提取角色、功能、场景三要素
2. **旅程生成 Prompt**: 要求生成按时间顺序的步骤，每步有明确目标
3. **任务拆解 Prompt**: 限制任务粒度为 2-4 小时，要求识别依赖关系
4. **验收标准 Prompt**: 要求生成 SMART 标准，至少 3-5 条

### 代码质量

1. **类型安全**: 全面使用 TypeScript，避免 any
2. **组件复用**: 抽取通用 UI 组件，遵循单一职责原则
3. **错误处理**: 所有 API 调用添加 try-catch，友好的错误提示
4. **性能优化**: 使用 React.memo、useMemo、useCallback 减少不必要渲染
